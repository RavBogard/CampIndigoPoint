# Phase 2 Plan 03: Harden Accessibility, Responsive Behavior, and Verification

## Objective
- **What:** Make the new shell resilient by explicitly implementing accessibility and responsive behavior patterns and introducing a lightweight verification baseline for future route work.
- **Why:** Phase 2 is where quality constraints become system-level norms; if accessibility and mobile behavior are left implicit, every later audience phase becomes riskier and noisier.
- **Output:** Focus-visible and reduced-motion support, improved mobile drawer semantics, responsive tuning for route pages, and a minimal shell test harness or equivalent automated verification path.
